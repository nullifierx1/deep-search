# Первый запуск веб-клиента

Бэкенд готов к интеграции по `/api/v1`. Проверены запуск API со встроенным каталогом, CORS для отдельного локального порта, валидация запроса и пустая история. Автоматические тесты покрывают поиск по локальному HTTP-сайту, прогресс, отмену, повтор по выбранным сайтам и восстановление истории после перезапуска.

## Для первой версии

- [x] Собрать основной сценарий в браузере с выбором сайтов, путями, настройками, результатами, отменой и повтором.
- [x] Восстанавливать открытую задачу после перезагрузки страницы. При `search_busy` открывать активную задачу из истории. Предусмотреть повтор подключения к API.
- [x] Отображать причины завершения по сайтам и сохранять доступ к частичным результатам после отмены.
- [x] Проверить основной сценарий из Chromium с локальным API и тестовым источником.
- [ ] Проверить несколько источников встроенного каталога в пользовательской сети.

## Выбор и добавление сайтов

- [ ] Сделать основным сценарием поиск по отображаемому имени. Пользователь вводит имя, выбирает один или несколько сайтов из подсказок и запускает поиск. Поддержать узнаваемые варианты написания, например Gmail и Google Mail.
- [ ] Добавить действие «Добавить сайт» рядом с поиском по каталогу. Предложить ввести имя и базовый адрес, проверить дубликаты и создать запись с настройками по умолчанию. Сайт должен сразу появиться в поиске по имени.
- [ ] Скрыть конструктор страниц из основного сценария. Обычный поиск использует готовую конфигурацию источника. Шаблоны URL, правила пагинации, ручные списки путей, число воркеров, таймауты, повторы и бюджет запросов перенести в «Расширенные настройки».

## Группировка адресов

- [ ] Добавить группы источников и адресов с собственным именем. Например, группа Google содержит Gmail (`mail.google.com`) и Drive (`drive.google.com`). Пользователь может выбрать один адрес или всю группу. При поиске по имени показывать группу и её отдельные источники.
- [ ] Сохранять отдельный ID, настройки доступа, статус и результаты каждого адреса. При выборе группы и отдельного источника внутри неё выполнять поиск по этому источнику один раз.

## Скорость и диагностика источников

- [ ] Разобрать поиск по ASMRfree, который, по наблюдению пользователя, не завершился за ожидаемое время. Замерить HTTP-загрузку, повторы, Playwright и пагинацию по отдельности. Добавить понятный прогресс и общий предел ожидания на источник.
- [ ] Классифицировать источники по времени до первого полезного результата. Начать с меток «быстрый», «обычный», «медленный» и «нет данных» по нескольким свежим запускам. Отдельно измерять общее время обхода, а запуски из кеша, отмены и блокировки исключать из оценки скорости. Показать метку рядом с именем сайта.

## Локальные профили

- [ ] Добавить локальные профили без регистрации и входа. В профиле хранить выбранные источники, группы, настройки поиска и историю. Переключение профиля должно переключать этот набор.
- [ ] Позволить создавать группы источников для профиля, например «Работа» или «Учёба». Хранить ссылки на записи общего каталога, чтобы обновление адреса сайта применялось во всех профилях.

## По мере интеграции

- [ ] Если отдельные команды запуска мешают первому старту, добавить одну команду для запуска API и веб-клиента. Зафиксировать зависимости установки для чистого окружения.
- [ ] Если фронтенду нужно генерировать типы и форму настроек, добавить машинно-читаемый контракт с типами, диапазонами и значениями по умолчанию. Пока контракт описан в [README](python_deep_search/README.md).
- [ ] Если частый опрос передаёт слишком много данных, измерить размер ответов и добавить облегчённую выдачу прогресса. Текущий ответ содержит прогресс и накопленные результаты.
